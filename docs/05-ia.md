# 05 — Inteligencia artificial

Proveedor: **Groq** (API compatible con OpenAI, `POST {url}/chat/completions`, `Authorization: Bearer {clave}`).
URL por defecto: `https://api.groq.com/openai/v1`.

| Uso | Modelo | Modo |
|-----|--------|------|
| Lectura de tickets (imagen) | `qwen/qwen3.8-27b` (fijo, independiente del modelo del chat) | `response_format: { type: 'json_object' }` |
| Sugerencia de coincidencias | `qwen/qwen3.8-27b` | JSON |
| Chat | Modelo configurado (por defecto `openai/gpt-oss-120b`) | *tool calling* |

> Los nombres de modelo cambian con el tiempo. Antes de implementar, verificar en la documentación de Groq qué modelos con visión y con *tool calling* están disponibles, y centralizarlos en una constante.

## 1. Llamada común

```json
{
  "model": "<modelo>",
  "messages": [...],
  "response_format": { "type": "json_object" },
  "temperature": 0.1,
  "max_completion_tokens": 8192
}
```

- **Reintentos**: ante HTTP 429, 500 o 503, reintentar tras 1,5 s, 4 s y 8 s. Si persiste 429/503: "El servicio de IA está saturado o se alcanzó el límite de uso. Esperá un minuto y probá de nuevo."
- **Respuesta cortada**: si `finish_reason === 'length'`: "La respuesta de la IA quedó cortada. Probá de nuevo o con una foto más recortada."
- **Parseo tolerante**: quitar bloques `<think>…</think>` y cercas ```` ``` ````; intentar `JSON.parse`; si falla, parsear desde el primer `{` hasta el último `}`; si falla, error "La IA devolvió una respuesta inválida. Probá de nuevo." (registrar el texto crudo en el log de desarrollo).
- **Límite de imagen**: Groq acepta hasta ~4 MB en base64; achicar antes (lado mayor ≤ 2000 px, JPEG calidad 0,85).

## 2. Lectura de tickets

Mensaje de usuario con dos partes: texto (prompt) + `{ type: 'image_url', image_url: { url: 'data:image/jpeg;base64,…' } }`.

**Prompt (literal de la web):**

```
Eres un experto en análisis de comprobantes. Analiza esta foto de comprobante/factura y extrae TODOS los items con sus detalles.

Devuelve SOLO un JSON válido con esta estructura exacta:
{
  "tienda": "nombre de la tienda o comercio",
  "items": [
    { "nombre": "descripción del producto", "cantidad": número, "precio_unitario": número, "total": número }
  ],
  "total_pagado": número,
  "observaciones": "notas si hay descuentos, impuestos, o datos incompletos"
}

IMPORTANTE:
- Extrae TODOS los items que veas, incluso si son pequeños
- Los precios deben ser solo números, sin símbolo de moneda
- Si no ves cantidad, asume 1. Las cantidades pesadas (ej: "0.535 UN x 119.00") van con decimales
- Si hay subtotal/total/impuestos/descuentos/forma de pago, no los incluyas como items — solo los productos reales
- total_pagado es lo que efectivamente se pagó después de descuentos (ej: "Pago total", "Total a pagar", descontando devolución de IVA / Ley 19210). Si no hay descuentos, es el total del comprobante. Nunca incluyas el cambio/vuelto
- Si la imagen está borrosa o no es un comprobante válido, devuelve items vacío y una observación clara
```

**Post-proceso:** `items` sin nombre se descartan; `total = Number(total) || 0`; `total_pagado = Number(...) || 0`.

## 3. Sugerencia de coincidencias

Se llama al elegir la categoría (y período) de uno o varios items. Entrada: items `{ idx, nombre }`, nombres de gastos existentes del período (sin repetir) y, opcionalmente, los que están **en el carrito** (pendientes con `enCarrito`). Si no hay gastos existentes, no se llama a la IA y todos quedan "Crear nuevo".

**Prompt:**

```
Tenés items de un comprobante de compra y una lista de gastos ya registrados en una categoría del presupuesto familiar.
Para cada item del comprobante, elegí el gasto registrado al que corresponde (por ejemplo "LECHE CONAPROLE 1L" corresponde a "Leche", "DETERG. NEVEX" a "Limpieza").
Si ninguno corresponde razonablemente, usá null.

Gastos registrados (usá el nombre EXACTO):
["Leche","Pan","Limpieza", ...]

De esos, el usuario montó estos al carrito durante la compra, así que son los más probables (preferilos ante la duda):   ← solo si hay
["Leche", ...]

Items del comprobante:
[{"idx":0,"nombre":"LECHE CONAPROLE 1L"}, ...]

Devolvé SOLO un JSON válido con esta estructura exacta:
{ "matches": [ { "idx": número, "gasto": "nombre exacto del gasto registrado" o null } ] }
```

**Validación:** solo se aceptan `gasto` que existan **exactamente** en la lista; cualquier otro valor se trata como `null`.

## 4. Chat con herramientas

### 4.1 Mensajes

```
system:  contexto completo (4.2)
user/assistant × 3: últimas preguntas y respuestas (assistant = JSON de la respuesta)
user:    pregunta actual
```

### 4.2 Contexto

**Parte automática** (se arma en cada pregunta con datos del presupuesto activo):

```
Sos el asistente financiero de "Números Claros", una app de presupuesto familiar en Uruguay (moneda principal UYU, algunas tarjetas en USD).
Presupuesto: {nombre}
Fecha de hoy: {AAAA-MM-DD}
Mes que el usuario está viendo: {Mes Año} ({AAAA-MM})

CÓMO ESTÁN ORGANIZADOS LOS DATOS
- Cada mes guarda: ingresos, gastos por categoría, tarjetas, comprobantes (tickets cargados) y un objetivo de ahorro.
- Los meses se piden en formato AAAA-MM (ej: 2026-09 es septiembre de 2026).
- Cada categoría de gastos se divide en períodos según su frecuencia: mensual (1), quincenal (2), cada 10 días (3) o semanal (una por semana de compra).
- Cada gasto (item) tiene: previsto (lo planeado), real (lo pagado o el monto esperado si está pendiente) y pagado (sí/no).
- Un item pendiente puede estar "en carrito": se fue montando en el súper pero todavía no se pagó.
- Los comprobantes son tickets de compra leídos con IA: tienda, fecha, total pagado, tarjeta usada y a qué gasto fue cada producto.
- Hay compras en cuotas (financiaciones) que se suman cada mes a una tarjeta de crédito.

REGLAS DE CÁLCULO (las herramientas ya devuelven los totales calculados con estas reglas)
- Gasto real del mes = items pagados en efectivo o débito + pagos hechos a tarjetas de crédito en ese mes.
- Un gasto pagado con tarjeta de CRÉDITO no cuenta como gasto real hasta que se paga la tarjeta; mientras tanto es deuda de la tarjeta.
- Un gasto pagado con DÉBITO cuenta en el momento y descuenta saldo de la cuenta.
- Pendiente = items no pagados (por su monto esperado) + saldo impago de las tarjetas de crédito.
- El objetivo de ahorro se trata como un gasto fijo del mes. Saldo libre = ingresos reales − gastos reales − objetivo de ahorro.

CATEGORÍAS DE GASTOS ACTUALES
- {nombre visible} (id: {id}, {frecuencia})

TARJETAS DEL MES QUE SE ESTÁ VIENDO
- {nombre}: {crédito|débito} en {moneda}

COMPRAS EN CUOTAS
- {concepto}: {N} cuotas de {monto} {moneda} en {tarjeta}

CÓMO TRABAJAR
- No inventes datos: usá las herramientas para obtener lo que necesites y pedí solo los meses necesarios.
- Para preguntas sobre una familia de productos o un tipo de gasto (ej: "¿cuánto gasté en lácteos?"): primero usá listar_gastos, elegí vos los nombres que pertenecen a esa familia (incluí abreviaturas y marcas) y después pasalos EXACTOS a sumar_gastos. Nunca sumes montos vos mismo.
- "Gastado" se refiere a lo pagado; mencioná lo pendiente aparte si lo hay.
- En la respuesta, listá qué gastos incluiste para que el usuario pueda verificar.
- Si una herramienta dice que un mes no tiene datos, decíselo al usuario.
- Respondé en español rioplatense, claro y breve.
```

**Notas del usuario:** texto libre en `presupuestos/{owner}/{pid}/_ia_contexto/notas`, agregado bajo el título `NOTAS DEL USUARIO (tenelas en cuenta, tienen prioridad)`.

**Formato de respuesta** (al final del contexto):

```
Cuando ya tengas los datos, respondé SOLO con un JSON válido (sin texto alrededor):
{ "titulo": "...", "explicacion": "...",
  "tabla": [ { "concepto": "...", "valor": "..." } ],
  "grafico": { "tipo": "bar|pie|line", "titulo": "...", "labels": ["..."], "data": [números] },
  "conclusion": "..." }
Omití "tabla" o "grafico" si no aportan.
```

### 4.3 Herramientas

Todas reciben meses en `AAAA-MM` (máximo **12** por llamada) y leen **solo** `presupuestos/{owner}/{pid}/{AAAA_M}` del presupuesto activo (el presupuesto lo fija la app, nunca la IA). Un mes inexistente devuelve `"Sin datos para este mes"`; un formato inválido, `"Formato inválido, usar AAAA-MM"`. Montos redondeados a 2 decimales. Dentro de una misma pregunta, cada mes se lee una sola vez (caché).

| Herramienta | Parámetros | Devuelve |
|-------------|------------|----------|
| `resumen_meses` | `meses[]` | Por mes: `ingresos {previsto, real, detalle[]}`, `gastos_por_categoria[] {categoria, previsto, real, cargado_a_credito, pendiente, items_pagados, items_totales}`, `tarjetas_credito {UYU, USD: {deuda, pagado, pendiente}}`, `objetivo_ahorro`, `totales_UYU {gasto_previsto, gasto_real, pendiente, saldo_libre, ahorro_neto}`, `comprobantes_cargados` |
| `detalle_categoria` | `categoria` (nombre o id; coincidencia exacta o parcial sin tildes), `meses[]` | Por mes: items `{periodo, nombre, previsto, real, pagado, en_carrito?, tarjeta?}`; error con la lista de categorías si no existe |
| `buscar_gastos` | `texto`, `meses[]` | Búsqueda literal (sin mayúsculas ni tildes) en nombres de gastos y productos de tickets: `gastos[]`, `productos_en_comprobantes[]`, `total_gastos_pagados`, `total_en_comprobantes` |
| `listar_gastos` | `meses[]` | `{ categoría: [nombres distintos ordenados] }` sin montos |
| `sumar_gastos` | `nombres[]` (exactos), `meses[]` | `por_mes {pagado, pendiente}`, `por_gasto {nombre: pagado}`, `total_pagado`, `total_pendiente`, `detalle[] {mes, categoria, periodo, nombre, monto, pagado}`, `nombres_no_encontrados?` |
| `comprobantes` | `meses[]`, `tienda?` | Por mes: `cantidad`, `total_pagado`, `tickets[] {tienda, fecha, total_pagado, tarjeta, productos[] {nombre, monto, registrado_en}}` |
| `tarjetas` | `meses[]` | Por mes: crédito `{deuda_del_mes, pagado, pendiente, cuotas[], gastos_cargados[]}`; débito `{saldo_inicial, saldo_actual, movimientos[]}` |
| `compras_en_cuotas` | `mes?` | `{ mes_referencia, compras[] {concepto, tarjeta, moneda, monto_cuota, cuotas_totales, inicio, activa_este_mes, cuota_de_este_mes, cuotas_restantes_despues} }` |

`sumar_gastos` y `listar_gastos` buscan **solo en las categorías** (no en tickets), por decisión del usuario, para no contar dos veces.

### 4.4 Ciclo

```
para ronda 0..4:
  respuesta = llamar(modelo, mensajes, tools = HERRAMIENTAS si ronda < 4, tool_choice: 'auto',
                     temperature 0.2, max_completion_tokens 4096)
  si no hay tool_calls: devolver parsear(respuesta.content) y la lista de consultas hechas
  agregar mensaje assistant { content, tool_calls }
  por cada llamada: ejecutar herramienta (errores → { error }), agregar mensaje
                    { role: 'tool', tool_call_id, content: JSON.stringify(resultado) }
error "La IA no llegó a una respuesta. Probá reformular la pregunta."
```

En la última ronda no se ofrecen herramientas para forzar una respuesta.

## 5. Privacidad de la IA

- A Groq se envía: la foto del ticket (achicada), nombres de gastos de una categoría/período, el contexto del presupuesto activo, las notas del usuario y los resultados de las herramientas pedidas.
- Nunca se envían: datos de otros presupuestos, claves, emails ni identificadores de usuario.
- Ver [07](./07-seguridad.md) para la recomendación de mover la clave a un backend.
